# 国会議員図鑑

国会議員の**集団を、いろいろな軸で切って見比べる**道具の試作です。一人ひとりの「何を約束し、何をしてきたか」まで、出典つきでたどれます。

- **一人＝一つの点**。横軸×縦軸のマスに点を並べ、色で三つめの軸を重ねる（同じ色は隣りあわせにまとめるので、マスごとの内訳が積み上げ棒のように読める）
- 軸：院・政党・性別・年代・当選回数・前職・地域・一番の得意分野・**公約の実現割合（AI判定）**・**国会での発言回数**・**議員立法の提出**
- 「問いから始める」ボタン（政党ごとの女性の割合、当選回数と発言の多さ、など）で、軸の組み合わせをすぐ試せる
- マスを選ぶと、その集団の**プロフィール**：人数・平均年齢・女性の割合・平均当選回数・発言回数の中央値（全体との比較つき）、公約の状況の内訳、よく掲げる分野、議員の一覧
- 名前や点を選ぶと、その議員の**ステータス画面**（公約クエスト・活動ログ。すべてに原文の引用と出典リンク）

色の決まり：区分に順序のない軸（政党・性別など）は、色覚の多様性に配慮して検証した順番のカテゴリ色。順序のある軸（年代・当選回数など）は青一色の濃淡。区分が9つ以上の軸（前職・地域など）は色分けには使わず、横軸・縦軸に使う。

## データ

- `data/members.json` … **実在の議員**（衆議院・参議院の現職）。基本属性だけで、公約・実績はまだ作っていない
- `data/sample.json` … 架空の議員713人のサンプル（公約・実績まで入っている。画面の見え方の確認用。実在の人物・政党とは関係ありません）

### 実在の議員の基本属性を取り込む（AI は使わない）

```sh
node scripts/import-roster.js --speeches   # 取得したページは .cache/ に保存。--refresh で取り直し
```

| 項目 | 出典と取り込み方 |
| --- | --- |
| 院・会派・選挙区・当選回数 | 衆議院：衆議院ウェブサイトの「議員一覧」。参議院：スマートニュース メディア研究所「国会議案データベース：参議院」（参議院ウェブサイトを整理した公開データ、MIT）※参議院ウェブサイトにはこの環境からつながらなかったため |
| 生年 | 公式の経歴の書き出し（和暦・西暦）から読む。読めないときだけ Wikidata |
| 経歴 | 公式の紹介ページの文をそのまま載せる |
| 性別 | Wikidata と名前（なければふりがな）で照合。**公式の「会派別の女性議員数」で検算**し、女性の数が公式と一致した会派で照合できなかった人は男性とする |
| 前職 | 経歴の文から、当選より前で最後に出てくる職業の手がかりで機械的に分類（**目安**） |
| 地域 | 選挙区を比例代表のブロックに当てはめる。参院比例は「全国」 |
| 国会での発言回数 | 国会会議録検索システム API で、2025-10-01〜2026-09-30 の発言の件数を数える |

発言回数の注意：委員長としての議事進行の発言も1件に数える。同じ期間でも、最近初当選した議員は国会にいた日数が短い。量であって、質を表すものではない。

## 動かす

```sh
cd giin-zukan
npm start               # http://localhost:8081
npm test                # 照合ロジックとデータの検証
npm run validate        # data/members.json の形と出典を確かめる
npm run build:preview   # dist-preview/index.html（1枚にまとめたプレビュー）
```

ビルドは不要（素の HTML / CSS / JS）。データは `data/members.json` だけです。

## 公開情報から AI でつくる

```sh
npm install
cp sources/_example.json sources/<議員id>.json   # 氏名・選挙区・性別・生年・前職・地域・公約ページの URL を書く
ANTHROPIC_API_KEY=... npm run generate -- sources/<議員id>.json
```

`scripts/generate.js` がすること：

1. **国会会議録検索システム API**（国立国会図書館）から本人の発言を集める
2. 設定に書いた**選挙公報・公式サイトの政策ページ**を取り込む
3. Claude に、構造化出力で「資料にあることだけ」から公約と実績を抜き出させる。出典は資料 ID と**原文そのままの引用**で返させる
4. **引用が本当に原文にあるかを機械で照合**し、見つからない出典は捨てる。出典が残らない公約・実績は丸ごと捨てる。判定の根拠が確かめられない公約は「判定できず」に落とす
5. 会議録 API の件数から「国会での発言回数」を記録する
6. `data/members.json` に `review.reviewed: false`（画面では「AI下書き・未確認」）で書き込む

人が出典を確かめたら `review.reviewed` を `true` にします。`npm run validate` は「実現・進行中・停滞」と判定した公約に根拠の出典がないと落ちます。

## 方針（公開前に必ず）

- **中立**：評価語を使わない。星は当選回数で、議員の優劣ではない。並び順の初期値はふりがな順。「発言回数」は量であって質ではないことを画面でも伝える
- **基本属性は公式の情報から**：院・政党・選挙区・当選回数・性別・生年は衆参の公式サイトなどの公開情報を、AI ではなく決まった手順で取り込む（AI に任せるのは公約と実績の抜き出しだけ）
- **出典が先**：出典のない記述は載せない。AI の判定は必ず「AI判定」と根拠を並べる
- **人の確認**：実在の議員を公開する前に、出典を人の目で確かめる。誤りの訂正窓口を用意する
- **写真を使わない**：肖像の権利を避けるため、データの色・髪型から描くちびキャラにしている
- **選挙期間中の扱い**：公職選挙法上の扱い（更新の止め方など）は、公開前に専門家に確認する

## 構成

```
giin-zukan/
  index.html, style.css, app.js   画面
  data/members.json               実在の議員（1行に1人。scripts/import-roster.js が書き出す）
  data/sample.json                架空のサンプル（scripts/make-sample.js が書き出す）
  sources/_example.json           生成の設定の雛形
  scripts/lib.js                  スキーマ・引用の照合・データ検証（純粋な関数）
  scripts/sample-crowd.js         架空の議員の集団（分析の見え方の確認用）
  scripts/roster-lib.js           名簿・紹介ページ・生年・地域・前職を読む純粋な関数
  scripts/import-roster.js        実在の議員の基本属性を取り込む
  scripts/generate.js             公開情報 → Claude → 照合 → data/members.json
  scripts/validate.js             データの検証
  scripts/build-preview.js        1枚の HTML にまとめる
  tests/                          node --test
```
